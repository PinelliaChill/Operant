# B2-5 项目知识治理

记录身份：Codex。范围只含 B2-5 / MP-4；当前交付状态和验收门禁见 [任务包](task-package.md)。

在实时 Core 模式进入“项目 → 管理知识 → 高级知识治理”，选择项目：

- **正式知识约定**：区分当前可用与被来源、时效阻止的记录。点击“对此记录提出修改”会带入记录和基准 revision；提交后形成候选，需再人工确认。
- **候选与冲突收件箱**：核对中文内容、来源数、有效时间、冲突关系与目标版本，再接受或拒绝。批量操作只处理页面选择的精确 Proposal/version；任何版本变化都会阻止整批接受。复核过期候选仍可拒绝。
- **冲突处理**：未解决的 `conflicts_with` 不能直接发布。可以拒绝冲突候选、对当前记录提出纠正；若确实应由另一条记录取代，提议时声明 `supersedes` 和目标精确版本。确认替代时，旧记录退役与新记录发布在同一事务完成。
- **原始历史搜索**：检索项目授权范围内的历史，点击展开读取原始来源。它描述查询当时发生的事实，不等于当前约定。撤销来源会阻止相关派生记忆后续使用，不会改写已发送的上下文。
- **后台整理与状态**：Host 后台开关默认关闭。开启后选择正式 ModelProfile，设置来源数与 Token 预算，创建一次有限整理任务。后台只能产生待审候选，不能自我确认。页面展示 Scheduler 状态、水位、模型和独立 Token 用量；未知美元成本不按零计算。
- **失败处理**：取消当前任务或在死信状态显式重试。重试保留固定来源和配置快照、累计调用次数与 Token；达到预算、配置变化或结果未知时应核对服务端状态，不自动重放。没有新来源不会调用模型。
- **实际使用检查器**：聊天中的“上下文检查器”保留当次实际发送内容，另标明当前来源、时效与冲突影响。

断线后页面保留已读取投影并禁止写入。恢复连接后重新读取，不把旧缓存或网络送达视为最新 Core 确认。

## 本地验证边界

本批使用持久隔离工作树、合成临时库和隔离原生构建，未迁移真实用户库、未部署。真实模型链路见 [live-05.json](live-05.json)，原生交互见 [native-acceptance.json](native-acceptance.json)。基础门禁首轮失败与补跑原样保留，详见任务包；独立审查是否完成以任务包为准。

Schema v17 增加治理、任务水位、幂等与事件表，历史 v1–v16 校验值保持不变。已有隔离库的迁移/回退测试不构成对真实用户库迁移的授权。关闭后台开关可停止新整理；关闭不能恢复已撤销来源或绕过审阅规则。
