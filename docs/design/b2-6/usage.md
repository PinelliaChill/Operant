# B2-6 经验技能与授权协作

在管理中心选择项目，进入“技能”或“知识”页中的“经验技能与授权协作”。所有状态来自本地 Core；操作完成后会显示 Core 回执。断线、协议不兼容或写结果未知时先刷新核对，不重复提交。

## 从经验生成技能

1. 选择有来源的已发布知识，整理为经验步骤；到知识治理中审阅候选。
2. 从已确认的步骤生成技能草稿。草稿固定来源版本和资源 hash，不能作为已发布技能使用。
3. 核对具体版本并验证，再发布。验证检查资料和来源一致性，不代表业务测试或模型效果评测通过，也不会增加工具权限。
4. 更新时先产生新步骤和新草稿；相同来源与内容会复用已有版本。停用后不再用于后续任务；回退只能选择当前仍通过来源与权限检查的历史版本。

来源纠正或撤销后，依赖它的技能会被阻断。已经发送给模型的内容无法收回；受污染历史不能继续自动发送。

## Writer 知识晋级

登记 Core 已初始化的 Git 工作区，核对 branch、commit 和 tree。Writer 经验先绑定对应 Run 与分支，未完成合并时保持候选。

成功合并后，选择 MergeRun 让 Core 检查实际目标 commit、tree 和干净状态，并生成验证工件；随后核对精确证据修订再晋级。该检查证明合并目标身份，原推断证据仍是推断。目标有未提交改动、tree 已变、登记或证据已撤销时，相关知识不再满足使用条件。

## 个人偏好、共享与移交

个人偏好需要选择来源并明确确认，保存在当前用户范围。跨项目使用需要另行创建授权，固定记录版本、目标项目、角色或模型、用途和期限。撤销授权会阻断后续使用，不声称删除消费者已经收到的内容。

数据集移交后，以 Registry 中的新所有者为准；原插件的旧绑定不能继续运行，原插件卸载也不能删除新所有者正在使用的数据。授权复制产生独立版本，不自动授予目的端更多权限。

## Remote 与 TUI

Remote 包必须指定目标、用途、期限、预算及精确知识版本。Target 上传的内容只进入本地候选，仍需 Core 核对和人工审阅。界面区分队列接收与 Target 完成。当前 B2-6 的 Remote 证据覆盖加密协议、注册/租约/队列与本地适配器；未验生产 HTTPS connector。

TUI 使用 `Alt+4`，输入项目 ID 后刷新。可查看版本、来源、Writer 验证、授权范围和包期限，并对技能验证/发布/停用/回退、Writer 晋级/撤销、共享撤销和包撤销进行精确对象确认。`Esc` 返回。创建草稿、登记、授权和包创建使用 GUI 或生成 Client。

本批保留 B2-4 已接受的 Host 性能限制，不包含 B2-7 综合候选发布，也不代表签名桌面版、公网部署或真实用户数据迁移完成。
