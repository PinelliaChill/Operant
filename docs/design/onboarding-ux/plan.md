> 2026-10-07；记录身份：Codex 主线程；适用对象：本轮实施与验收 Agent。

> 状态：实施中。逐项实现、验收和证据统一维护于 [验收记录](acceptance.md)，计划不是完成证明。

## 目标与默认选择

默认提供通用任务助手，连接模型后直接开始对话。支持 ChatGPT、Gemini OAuth；一级导航为对话、项目、协作、任务，底部设置。高级能力保留，各项配置只有一个管理页面。

首次使用以“连接模型 → 选择默认模型 → 开始对话”为主流程，不要求用户先理解模型配置、角色、会话绑定和权限体系。首次引导可跳过，连接成功返回原输入草稿。

| UX-02 | 默认角色未接入首次配置，侧栏强制新建角色 | 模型连接后初始化默认角色；通用助手可直接使用，已有用户配置保持原值 |

| UX-05 | API 入口难找，要求填写环境变量名 | 首次连接入口；常用表单仅服务商、密钥、模型；密钥由本机凭据流程管理 |
| UX-06 | 可选参数与必要字段同时展开 | 默认采用模型能力和服务默认值；温度、上下文、预算等折叠到高级选项 |

| UX-08 | 未配置扫描目录时技能发现报 422 | 自动登记常见目录；缺失目录跳过，无目录为空结果，错误给出可操作入口 |
| UX-09 | 普通 metadata、多行 description 被拒绝 | 安全、受限的标准 YAML frontmatter；坏技能不阻断其他技能 |
| UX-10 | 技能链接与重复来源处理不足 | 登记根内核对真实路径并去重；目录外目标须显式登记，不扩大权限 |
| UX-11 | 随 Core 分发的内置技能在空工作区仍不可用 | 初始化默认工作区时接入内置技能；外部技能发现后由用户选择启用 |
| UX-12 | 未绑定 Session 的会话先报技能读取错误 | 根据会话就绪状态加载；空会话展示开始入口 |
| UX-13 | 本机操控要求手填 Bundle ID、Origin、SHA 等 | 能力卡片、应用选择、网站目标授权；手动操控台、包摘要与原始参数进入高级区域 |
| UX-14 | 设置默认打开记忆管理，多入口重复同页 | 唯一管理页面、内容与配置分开、设置分类及旧链接重定向 |
| UX-15 | 各页下拉选择控件和风格不同 | 共用可搜索选择组件；统一样式、选中态、弹层、键盘及焦点 |
| UX-16 | 协作要求先准备团队和流程运行 | 可用基础模板；默认选模板、输入任务开始，成员和流程编辑进入高级配置 |
| UX-17 | 常驻内部说明、晦涩用词和原始错误 | 删除无必要说明；使用对话、成员、目标、计划；动态错误说明原因和下一步 |

## 三批实施

### 第一批：首次使用与正常对话

- 建立可跳过的首次引导，完成连接后回到原草稿；默认创建应用管理的个人工作区，操作其他文件夹时再选择。
- 初始化通用、规划、探索、编程、审查角色，采用所选模型支持的参数，不覆盖用户角色与配置。
- 统一会话初始化命令，由后端创建或补齐 Thread、Session 和不可变执行快照；命令使用幂等键，未知写结果不自动重放。
- 增加标题元数据及更新命令；侧栏、标题栏、选择器共用名称。默认使用首条消息的短内容，手动名称优先。
- 密钥在唯一连接页输入后交给本机处理，保存于受保护且不提交的 `.env`；数据库、日志与公开投影只保留引用。
- 高级参数默认收起。未知上下文窗口保持未指定，温度默认不发送，不猜测模型能力。

### 第二批：OAuth 与技能发现

- ChatGPT 使用 Operant 的真实应用标识和官方 dynamic registration、PKCE/OIDC、账号绑定、续期与撤销，通过 Responses Provider 接入现有 Agent Loop。参考 [官方登录流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[模型调用要求](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)及[当前限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。
- Gemini 使用官方 API OAuth 和 Operant 桌面 OAuth 客户端，首次处理用户的 Google Cloud 项目、后续复用；原生 Provider 统一流式输出、工具调用、用量和取消。[官方 OAuth 文档](https://ai.google.dev/gemini-api/docs/oauth)。
- 登录取消、授权不足、续期失败和额度不足保留对话，提供重新连接；分别记录账号登录与模型可用状态。
- Core 扫描内置目录、`~/.agents/skills`、`~/.codex/skills`、`~/.claude/skills`，以及当前工作区的对应目录。启动与工作区改变刷新相关目录，不在每次渲染重复扫描。
- 按 [Agent Skills 规范](https://agentskills.io/specification)支持元数据、多行说明与资源目录，保留大小、深度、条目、安全和安装完整性检查。
- 自动发现只建立目录，不自动运行技能脚本或授予工具权限；坏技能返回具体问题，不阻断其余技能。

### 第三批：导航、工具使用和文案

- 设置分为常规、模型连接、助手与角色、工具与扩展、记忆、权限与高级。引导与对话提示复用唯一设置表单。
- 任务页承载任务、待审批和定时任务；项目页承载文件与知识内容，配置不混入内容页。旧链接重定向至唯一页面。
- 工具按“启用 → 选择目标 → 在对话中使用”组织；能力卡片说明用途、状态和下一步。手动操控台、原始 JSON/Schema、外部包摘要和调试信息进入高级区域。[ChatGPT 连接流程参考](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)。
- 基础团队模板可从输入任务直接启动；高级编辑能力保留，不把定义编辑和运行状态混为同一权威。
- 共用选择组件覆盖模型、角色、团队、项目和权限范围，验证深浅主题、窄屏、遮挡及焦点。
- 删除“审计请求和状态变更均由服务端返回结果”“将有来源的经验整理为步骤”等常驻说明；必要动态提示用具体行动，例如“结果尚未确认。请刷新查看，暂时不要重试。”

## 公共接口与兼容

新增版本化 `onboarding.v1`，承载标题元数据、模型连接、首次配置状态及对应命令/查询。单一 Schema 生成 TS/Python Client，保留旧协议及其 digest；新增能力不得伪装为旧客户端已有能力。

配置、SQLite、普通日志和公开投影只保存凭据引用；本机凭据录入与 OAuth 回调受本机连接、可信 Origin 和权限限制。现有 Action Gateway、Policy DENY、审批、预算、未知结果不重放及不可变快照约束继续有效。

同步 `docs/PROJECT_ARCHITECTURE.md` 的实际实现，`docs/UI_UX_DESIGN_SPECIFICATION.md` 的目标客户端，以及 `docs/项目架构.md` 中受影响的 Kernel 契约。主线程负责公共接口、集成和最终交付，接口明确后按路径分配后端与前端实现。

## 验收与交付

- 干净数据连接 API/OAuth 后直接发送第一条消息，不填写角色、系统提示词、环境变量名或手动绑定运行。
- 名称重启保留；自动名称不覆盖手动名称；重复点击、切换、断线不重复运行或串写。
- ChatGPT 与 Gemini 均完成真实登录、模型发现、流式回复、工具调用、续期与撤销；外部配置缺失或真实调用受阻明确记为未通过，不删出范围。
- 覆盖常见技能目录、标准格式、链接、重名、损坏文件、来源变化、权限边界，并通过真实会话产出结果。
- 原生桌面壳验证本机能力首次启用、目标选择、实际操作、接管/取消及基础团队任务。
- 核对唯一入口、旧链接、键盘操作、深浅主题和窄屏；逐页清理无必要说明和裸露内部错误。
- 按实际影响运行基础门禁、客户端测试/类型/构建、协议生成确定性和必要真实链路。复用匹配版本的有效证据，避免重复按按钮或按编号验收。

终点为可审阅代码、隔离桌面候选和真实验收记录。合并、发行、安装版更新和真实用户库迁移沿用已有授权边界；各批同时核对完整 UX-01～UX-18 清单，阶段通过不替代整轮完成。
