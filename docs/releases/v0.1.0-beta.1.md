# Operant v0.1.0-beta.1

这是 Operant 的首个 GitHub Beta 源码预发布，适合愿意从源码安装、体验与反馈问题的开发者。
本次发布固定到明确 Git 提交，不提供已签名桌面安装包，也不发布到 PyPI。

## 这个版本可以做什么

- 配置模型与角色，让规划、只读探索、编码、审查和汇总角色分工运行。
- 通过本地 Core 统一管理会话、工作流、工具权限、审批、历史和文件产物。
- 使用 React 网页、基础 Web 工作台、可选 TUI 或 Tauri 壳连接本机服务；实时连接出错时明确提示。
- 使用带来源、作用域和版本记录的记忆。插件需要显式安装和启用。B2-1～B2-3 提供记忆插件协议、隔离宿主、两个示例插件，以及安装、开关、保留/删除和基础管理流程。
- 通过 MCP 工具、受控 Skill 发现和生成客户端扩展能力。

本批同时补齐了开源维护基础：轻量 main 保护、密钥推送拦截、依赖漏洞提醒、CodeQL 默认扫描（Python、JavaScript/TypeScript、Actions）、按范围运行的 Python/GUI CI，以及中文反馈模板和社区准则。

## 从源码安装

```bash
git clone --branch v0.1.0-beta.1 --depth 1 https://github.com/PinelliaChill/Operant.git
cd Operant
uv sync --frozen --extra dev
cp .env.example .env
uv run operant init
```

需要 Git 和 uv。用编辑器在 `.env` 中配置自己的模型地址与 API Key，然后按 README 的「快速开始」创建模型、只读角色和会话。

```bash
uv run operant model discover
uv run operant serve --host 127.0.0.1 --port 8000
```

访问 [本机工作台](http://127.0.0.1:8000/web)。React 界面另需 Node.js 22.6+，安装与启动方式见 README。
默认编码角色执行命令需要 Docker 和合适镜像；只读体验不需要 Docker。

## 验证与边界

- 本次 PR16 修复仅去掉测试对开发机临时路径的依赖；产品代码沿用已交付 B2-1～B2-3，并在当前 Python 3.10/3.12 与 GUI 检查中复核。
- 历史真实模型/原生证据的范围见仓库交付记录。本次维护没有重跑真实模型或桌面壳，不将自动测试等同于完整真实场景验收。
- B2-4 及后续工作不在本次标签中。GUI 拖拽编排和默认裁判模型等目标能力不全部等于当前可用功能。
- 新用户建议使用新数据库体验。已有用户升级前先备份；SQLite 升级可能不支持直接降级，不要让旧版本接管新库。
- 默认只监听本机；远程能力没有公网部署验收。运行数据中可能含私有代码，发送给在线模型的内容会交给对应服务商。
- 桌面产物尚未签名、公证，未提供自动更新。当前 GitHub 默认配置 API 未接受 Rust 语言，因此本次 CodeQL 不覆盖 Rust 壳。本次 Release 的附件仅为 GitHub 提供的源码归档。
- 安全扫描已经启用，但告警尚未全部核查关闭：依赖告警涉及 cryptography 和 glib，CodeQL 对部分路径处理和界面数据保存提出了待复核提示。没有把这些结果标记为误报或声称已全部修复，后续修复应经兼容性测试后发布。

问题反馈请使用仓库 Issue 模板；安全漏洞请通过 Security 页面私密提交。项目采用 Apache-2.0 许可证。
